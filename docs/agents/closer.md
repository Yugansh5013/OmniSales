# 🎯 Closer Agent

The **Closer Agent** (`:9001`) is an autonomous deal acceleration and objection handling worker. It monitors active pipeline opportunities, identifies deal stall conditions, analyzes buyer sentiment from conversation threads, queries competitive intelligence via the **Google A2A protocol**, drafts context-aware responses, and automatically advances CRM deal stages upon human approval.

---

## 1. Architectural Overview

The Closer Agent is implemented as a **LangGraph cyclic state graph** with state persistence backed by PostgreSQL (`PostgresSaver`). It executes deterministic risk classification and objection handling before pausing at a strict human approval checkpoint (`interrupt_before=["human"]`).

```mermaid
flowchart TD
    START([Start / Trigger]) --> ANALYZE[analyze_deal]
    ANALYZE --> CLASSIFY[classify_risk]
    
    CLASSIFY -->|healthy / won / lost| FINISH([No Action Needed])
    CLASSIFY -->|at_risk & objection| SPY_CHECK{Competitor Mentioned?}
    CLASSIFY -->|at_risk & stall| FOLLOWUP[draft_followup]
    
    SPY_CHECK -->|Yes| SPY_A2A[query_spy_a2a\nGoogle A2A Protocol :8080]
    SPY_CHECK -->|No| OBJECTION[handle_objection]
    SPY_A2A --> OBJECTION
    
    OBJECTION --> DRAFT[draft_response]
    FOLLOWUP --> DRAFT
    
    DRAFT --> HITL[interrupt_before: Human Gate\nQueue in agent_tasks]
    HITL --> APPROVE{Rep Approves?}
    
    APPROVE -->|Approve| SEND[Dispatch Resend Email\nAdvance Deal Stage in CRM]
    APPROVE -->|Reject with Feedback| REGEN[/regenerate Loop]
    REGEN --> DRAFT
```

## 2. LangGraph State Machine

### State Schema (`CloserState`)
The agent maintains a structured state throughout its reasoning cycle:

| Field | Type | Description |
| :--- | :--- | :--- |
| `deal_id` | `str` | UUID of the deal under analysis |
| `org_id` | `str` | Multi-tenant organization identifier |
| `deal_data` | `dict` | Deal attributes (ARR, stage, contact, company, close date) |
| `thread` | `list[dict]` | Historical email thread with timestamps and sender metadata |
| `risk_level` | `str` | Classified risk: `healthy`, `at_risk`, or `critical` |
| `risk_reasoning` | `str` | Natural language explanation generated by LLM |
| `competitor` | `str | None` | Extracted competitor name (e.g., `AcmeCRM`) |
| `battlecard` | `dict | None` | Live battlecard fetched from Spy Agent |
| `draft_email` | `dict | None` | Subject line, body copy, and metadata |
| `task_id` | `str | None` | ID of the queued approval task in `agent_tasks` |

### Graph Nodes
1. **`analyze_deal`**:
   - Queries the FastMCP CRM Server (`get_deal`) to fetch ARR, current pipeline stage, last activity date, and full conversation thread (`closer_thread`).
2. **`classify_risk`**:
   - Uses `shared.llm.COMPLEX_LLM` (`openai/gpt-oss-120b`) to analyze the thread.
   - Evaluates:
     - **Silence duration** (e.g., >7 days post-pricing).
     - **Buyer objections** (pricing, feature parity, competitor displacement, implementation time).
     - **Scheduling signals** (requests for demo, contract review, or executive meetings).
3. **`query_spy_a2a`**:
   - Dynamically extracts the competitor name from the conversation.
   - Invokes the **Spy Agent** via HTTP Google A2A protocol:
     `POST http://spy-a2a:8080/a2a/battlecard`
   - Ingests differentiators, weaknesses, and pricing counter-strategies.
4. **`handle_objection` / `draft_followup`**:
   - Merges the deal context, thread history, and battlecard.
   - Synthesizes an executive-grade email defending commercial margins and proposing next steps.
5. **Human Approval Gate**:
   - Serializes graph state into PostgreSQL.
   - Registers a pending record in `agent_tasks` with `status = 'pending_approval'`.

## 3. Live Deal Stage Movement

When a sales representative approves a Closer task in the dashboard:
1. **Email Dispatch**: The draft is dispatched via Resend to the customer, stamped with a hidden tracking header `[ref:xxxxxxxx]`.
2. **Stage Progression**: Closer updates the deal's stage in PostgreSQL and invokes `update_hubspot_deal_stage`:
   - If previous stage was `proposal`, advances to **`negotiation`**.
   - If previous stage was `negotiation`, advances to **`contract_sent`**.
   - If a payment link was generated, advances to **`closed_won`** upon confirmation.
3. **Audit Logging**: An immutable audit log entry is written to `audit_trail`.

---

## 4. Inbound Reply Loop & Regeneration

- **Inbound Poller**: When a prospect replies, `api-gateway`'s IMAP watcher extracts the `[ref:xxxxxxxx]` tag, appends the buyer's reply to `deals.closer_thread`, and invokes:
  `POST http://closer-agent:9001/trigger/{deal_id}`
- **Feedback Re-evaluation**: If a rep rejects a draft with corrections (e.g., *"Make it shorter and offer Net 45"*), the dashboard calls:
  `POST http://closer-agent:9001/regenerate/{task_id}`
  Closer ingests the rep's feedback, rewrites the copy, and queues a revised draft.
